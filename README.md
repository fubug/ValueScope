# 投资面板（ValueScope v4）

一个纯静态的投资决策面板：**全球主要市场估值对比 + A 股个股价值分析 + 行业看法**。
Astro 构建，GitHub Pages 自动部署，数据就是仓库里的 JSON，改完提交即上线。

## 在线访问

`https://fubug.github.io/ValueScope/`（push 到 main 后 1-2 分钟自动部署）

## 页面结构

| 路径 | 内容 |
|---|---|
| `/` | 全球市场横向对比：PE / PB / 股息率 / 估值分位 / ERP / 性价比档位 |
| `/markets/[id]` | 单市场详情：5/10/20 年分位、口径问题、判定链、人工结论 |
| `/stocks` | A 股个股：三层过滤器总表（卡在哪一层一眼可见）+ 按距买入价排序的分组 |
| `/stocks/[ticker]` | 个股详情：三层校验、合理价值区间、估值方法、反证条件 |
| `/etfs` | ETF 工具：底层指数估值 + 三层（成本/估值/可用），溢价换算成费率年数 |
| `/etfs/[code]` | ETF 详情：溢价警示、三层校验、申购状态、指数口径提示 |
| `/undervalued` | 低估值扫描：破净分布、股息分层，以及「为什么这些板块测不准」 |
| `/sectors` | 行业看法：每条观点必须带反证条件 |
| `/method` | 方法论：判定规则、数据来源、已知局限 |

## 设计原则

1. **没有综合评分。** 上一个版本（v3）的五维加权「鱼情分」被废弃：权重是拍的，没人验证过分数与收益的关系。现在只用「主估值分位落档 + ERP 修正」两步，每步可复算、可反对。
2. **缺数据就留空，不编数字。** 页面上所有「待接入」都是真实缺口（如长期年化/夏普），比一个好看的假数字有价值。
3. **每个观点必须可推翻。** 行业观点与个股分析都强制携带「反证条件」，条件出现就必须改结论。
4. **便宜和该买是两件事。** 「便宜但不买」是独立分类，防止把低估值当买入理由。

## 数据维护

```bash
npm install
npm run check   # 数据校验（字段完整性 + 新鲜度，提交前必跑）
npm run dev     # 本地开发 http://localhost:4321/ValueScope/
npm run build   # 构建到 dist/
```

| 文件 | 改什么 |
|---|---|
| `data/markets.json` | 市场估值快照。改 `snapshot` 日期，核对分位口径后填入 `percentiles` |
| `data/stocks.json` | 个股。新增一只必须填 `certainty`（高/中/低确定性）、`payoutRatio`、`anchorNote`、`veto`；status 与买入价自动派生，不要手填 |
| `data/etfs.json` | ETF 工具。indices 放底层指数估值（必须带 sources 与口径说明），etfs 放工具成本（溢价/费率/申购状态）。溢价为空必须用 note 说明，填了必须与 price/nav 自洽 |
| `data/screen.json` | 低估值扫描的板块级统计（破净分布、盲区说明），不放个股结论 |
| `data/sectors.json` | 行业观点，更新 `pePercentileBasis` 的数据日期 |

## 已知缺口

- **长期年化收益 / 夏普比率 / 最大回撤**：所有市场均未接入。免费行情接口（stooq / Yahoo / 东财）在本环境不可用。补数方式：把指数月度收盘价放到 `data/series/<id>.csv`，脚本自动计算（待实现），比抄第三方数字可信。
- **欧洲 STOXX 600**：本次快照未取得可信估值，字段留空。

## 部署

`.github/workflows/deploy.yml`：push 到 main → 校验数据 → 构建 → 发布到 Pages。
校验不过（字段缺失、结论无反证条件等）会直接卡住部署，这是故意的。
